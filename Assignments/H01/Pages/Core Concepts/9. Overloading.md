# Overloading in C++
**Overloading** is a form of compile-time polymorphism that allows you to define multiple functions or operators with the same name within the same scope, provided they have different **function signatures**.

### Types of Overloading
1. Function Overloading: Function overloading allows you to define multiple functions with the same name as long as they have different parameter lists (signatures).
   - **Criteria for Overloading:**
     - Different Number of Parameters: e.g., sum(int a) vs sum(int a, int b).
     - Different Types of Parameters: e.g., print(int i) vs print(double d).
     - Different Order of Parameters: e.g., move(int x, double y) vs move(double x, int y).
   - **What Does NOT Count:**
     - Return Type: You cannot overload based solely on return type.
     - Default Arguments: Functions differing only by default arguments are considered multiple deinitions, not overloads, and can cause ambiguity errors.

2. Operator Overloading: Operator overloading allows you to redefine how standard C++ operators (like +, -, *, <<) behave when used with user-defined types like classes and structures. 
   - **Common Use Cases:**
     - Arithmetic: Redefining + to add two ComplexNumber or Matrix objects.
     - Input/Output: Overloading << for ostream to print objects directly via cout.
     - Subscripting: Overloading [] for custom container classes.
   - **Operators that CANNOT be Overloaded:**
     - Scope resolution (::).
     - Member access or dot operator (.).
     - Ternary operator (?:).
     - Object size (sizeof) and type identification (typeid).

3. Constructor Overloading: Classes can have multiple constructors with the same name (the class name) but different parameters to provide multiple ways to initialize an object. 
  - **Example:** A Circle class might have a default constructor Circle(), a Circle(double radius), and a Circle(int x, int y, double radius). 

### Overloading vs Overriding
These are different concepts, fundamentally.

| **Feature** | **Function Overloading** | **Function Overriding** |
| --- | --- | --- |
| **Scope** | Same scope/class.	| Different scope (Base vs. Derived). |
| **Signature** | Must be different. | Must be identical. |
| **Binding** | Compile-time (Static). | Runtime (Dynamic). |

## Code Example
```cpp
#include <iostream>
using namespace std;

// Overloaded function: takes two integers
int add(int a, int b) {
    return a + b;
}

// Overloaded function: takes three integers
int add(int a, int b, int c) {
    return a + b + c;
}

// Overloaded function: takes two doubles
double add(double a, double b) {
    return a + b;
}

int main() {
    cout << "Sum (2 ints): " << add(5, 10) << endl;       // Calls first version
    cout << "Sum (3 ints): " << add(5, 10, 15) << endl;   // Calls second version
    cout << "Sum (2 doubles): " << add(5.5, 10.2) << endl; // Calls third version
    return 0;
}
```

## Why It Matters
1. **Improved Readability and Usability:** You can use a single, intuitive name for functions that perform similar actions on different data types (e.g., print(int) and print(string)).
2. **Operator Overloading:** Custom objects can use standard syntax (e.g., object1 + object2 instead of object1.add(object2)), making code cleaner and easier to read.
3. **Simplified APIs:** Simplified APIs: It reduces the cognitive load on programmers by reducing the number of unique function names they need to memorize.
4. **Flexibility and Consistency:** Overloading permits the same function name to handle different numbers or types of arguments, crucial for designing flexible APIs.
5. **Enhanced Maintenance:** Because related operations share a name, it makes the code easier to manage and understand, particularly in large, collaborative projects. 

## Common Mistakes
### Function Overloading Mistakes
1. **Overloading by Return Type Only:** The compiler distinguishes overloads based on parameter lists, not return types [14, 40]. For example, int f() and double f() cannot coexist in the same scope.
2. **Ambiguous Calls:** Creating overloads with parameter types that are too similar (e.g., int vs long) can lead to compiler errors if an argument matches both equally well through Standard C++ Conversions.
3. **Ignoring `const` and References:** Misunderstanding how const parameters or reference qualifiers (like & vs &&) affect overload resolution can lead to calling the wrong function.
4. **Typedef Confusion:** Using C++ typedefs to "create" new overloads is a mistake; typedef only creates an alias. void f(char*) and void f(PSTR) (where PSTR is char*) are considered identical and will cause a conflict. 

### Operator Overloading Mistakes
1. **Violating Natural Semantics:** Changing the expected behavior of an operator (e.g., making + perform subtraction) leads to highly confusing and error-prone code.
2. **Loss of Short-Circuiting:** Overloading logical operators like && or || is dangerous because the overloaded versions do not support short-circuit evaluation, unlike the built-in versions.
3. **Inconsistent Operator Sets:** If you overload +, users also expect += to be available and behave consistently. Failing to provide the full "family" of related operators can frustrate uses.
4. **Member vs. Non-Member Confusion:** Some operators, such as C++ Stream Insertion <<, must be non-member functions to allow a non-class type (like std::ostream) on the left-hand sides.
5. **Attempting to Overload Non-Overloadable Operators:** Trying to overload restricted operators like ., ::, sizeof, or ?: will result in a compilation errors.
6. **Changing Precedence or Arity:** You cannot change the number of operands (arity) or the precedence of an operator. For example, overloading ^ for exponentiation is a mistake because its low precedence will lead to unexpected evaluation orders like a + b ^ c being parsed as (a + b) ^ c.
