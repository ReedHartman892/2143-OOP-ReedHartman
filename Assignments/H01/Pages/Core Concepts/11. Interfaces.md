# Interfaces in C++
There is no specific `interface` keyword in C++ like there is in Java or C#. Instead, interfaces are implied using **Abstract Classes** containing only **Pure Virtual Functions**.

## Code Example
``` cpp
// Interface (Abstract Class)
class IShape {
public:
    // Pure virtual function
    virtual void draw() = 0;

    // Virtual destructor is essential for proper cleanup
    virtual ~IShape() {} 
};

class Circle : public IShape {
public:
    void draw() override {
        // Implementation for drawing a circle
    }
};
```

## Why It Matters
- **Decoupling and Loose Coupling:** Interfaces allow high-level logic to interact with services without knowing their internal implementation. This means you can swap one implementation for another (e.g., changing a database or renderer) without modifying the code that uses it.
- **Polymorphic Behavior:** They enable runtime polymorphism, allowing objects of different classes to be treated uniformly through a common base pointer. This is critical for managing collections of different but related objects.
- **Unit Testing and Mocking:** Interfaces are vital for Test-Driven Development (TDD). You can inject "mock" or "fake" implementations into your system to test business logic without relying on expensive resources like real hardware or databases.
- **Enforcing Design Contracts:** The compiler ensures that any class "signing" the interface contract must implement all its methods. This prevents errors by guaranteeing that required functionality is present.
- **ABI Stability:** Using interface classes can reduce physical dependencies. Changes to an implementation do not force a recompilation of client code as long as the interface remains stable. 

## Common Mistakes
1. **Forgetting a Virtual Destructor:** This is one of the most critical errors. If an interface is used to delete a derived object and the destructor is not marked `virtual`, the derived class's destructor will not be called, causing memory leaks or resource mismanagement.
2. **Object Slicing:** Attempting to pass objects of a derived class by value into a parameter of the interface type causes "slicing," where the derived parts are stripped away and only the base interface remains. 
3. **Calling Virtual Functions in Constructors/Destructors:** When you call a virtual function from within a base class constructor or destructor, C++ calls the version of that function defined for the base class, not the derived class, because the derived object is not yet fully formed or is already partially destroyed. 
4. **Overusing Interfaces:** C++ supports multiple paradigms; over-abstracting everything with interfaces when simple functions or templates would suffice adds unnecessary complexity and performance overhead from virtual table (vtable) lookups. 
5. **Transferring Ownership via Raw Pointers:** Passing a raw pointer as a return value from an interface creates ambiguity about who is responsible for deleting the object, leading to potential leaks. 
6. **Violating the Interface Principle (Hidden State):** Interfaces should define a contract, not implementation details. Including non-const global variables or complex private data within the interface class breaks encapsulation and makes the interface harder to test and reuse.
