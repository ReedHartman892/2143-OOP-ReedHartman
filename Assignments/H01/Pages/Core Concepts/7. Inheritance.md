# Inheritance in C++
A fundamental pillar of Object-Oriented Programming that allows a new class **(derived class)** to acquire the attributes and methods of an existing class **(base class)**. It facilitates code reusability and establishes a hierarchical "is-a" relationship between objects.

### Types of Inheritance 
C++ supports five models: single, multiple, multilevel, hierarchial, and hybrid.
 - **Single Inheritance:** A derived class inherits from exactly one base class.
 - **Multiple Inheritance:** A derived class inherits from more than once base class.
 - **Multilevel Inheritance:** A class is derived from another derived class, forming an inheritance chain.
 - **Hierarchical Inheritance:** Multiple derived classes are created from a single base class.
 - **Hybrid Inheritance:** A combination of two or more of the above inheritance types, often leading to the **Diamond Problem**

### Visibility Modes
| **Base Member** | **Public Inheritance** | **Protected Inheritance** | **Private Inheritance** |
| --- | --- | --- | --- |
| **Public** | Public | Protected | Private |
| **Protected** | Protected | Protected | Private |
| **Private** | Inaccessible | Inaccessible | Inaccessible |

*Private members of a base class are never directly accessible to its derived classes.*

### Key Concepts
- **Constructor & Destructors:** Constructors are called in order from base to derived, while destructors execute in reverse (derived to base).
- **Function Overriding:** A derived class can provide its own implementation of a base class function. To enable this dynamically, the base function must be marked `virtual`.
- **The Diamond Problem:** This occurs in hybrid inheritance when a class inherits from two classes that share a common base. C++ resolves this ambiguity using Virtual Inheritance.
- **Benefits:** It promotes *code reusability*, reduces redundancy, and enables *polymorphism*.

### Basic Syntax
```cpp
class Base {
public:
    void display() { std::cout << "Base class"; }
};

// Public inheritance from Base
class Derived : public Base {
public:
    void show() { std::cout << "Derived class"; }
};
```

## Why It Matters
Inheritance enables developers to create hierarchical relationships that mirror real-world logic, such as a "Dog" being a type of "Animal".

1. **Code Reusability:** It allows you to reuse tested code from a base class without rewriting it in every derived class.
2. **Dynamic Polymorphism:** Public inheritance is the mechanism for runtime polymorphism. By using virtual functions, a base class pointer can call the specific implementation of a derived class at runtime, allowing code to handle different object types through a unified interface.
3. **Maintainability:** Shared functionality is centralized in the base class. If you need to update a common behavior, you only change it in one place, and the update is reflected in all subclasses.
4. **Abstraction and Interface Design:** You can define abstract classes with pure virtual functions to act as "contracts". This ensures that all derived classes implement essential behaviors while hiding their complex internal details.
5. **Memory and Efficiency:** In advanced C++, techniques like the *Empty Base Optimization (EBO)* allow a derived class to inherit from an empty base without increasing the object's size, which is critical for memory-efficient standard library components like std::vector allocators.

## Common Mistakes
#### Core Implementation Errors
 - **Non-Virtual Destructors:** If a base class has a non-virtual destructor, deleting a derived object through a base class pointer causes undefined behavior (often a memory leak because the derived part is never cleaned up).
 - **Object Slicing:** Assigning a derived object to a base class object by value "slices off" the derived data and methods, leaving only the base portion and destroying polymorphic behavior.
 - **Calling Virtual Functions in Constructors/Destructors:** In C++, an object’s type changes during construction. Calling a virtual function in a base constructor will invoke the base version, not the derived version, because the derived part does not yet exist.
 - **Shadowing Base Members:** Defining a variable in a derived class with the same name as one in the base class "shadows" it. This often leads to bugs where developers update the derived variable while base methods continue to use the original, hidden one.

#### Design & Logic Pitfalls
 - **Violating the Liskov Substitution Principle (LSP):** A common mistake is using inheritance for classes that are only "almost" a kind of the base.
 - **"Is-A" vs. "Has-A" Confusion:** Overusing inheritance for code reuse (implementation inheritance) instead of modeling a true "is-a" relationship. In many cases, composition (having a member object) is safer and more flexible.
 - **Deep Inheritance Hierarchies:** Creating overly deep trees makes the codebase rigid, increases tight coupling, and makes debugging difficult as behaviors are scattered across many layers.

#### Multiple Inheritance Issues
 - **The Diamond Problem:** When a class inherits from two classes that share a common base, it may receive two copies of that base class's members. This creates ambiguity that must be resolved using virtual inheritance.
 - **Function Name Ambiguity:** Inheriting from two base classes that both define a function with the same name causes a compiler error when the function is called, requiring explicit scope resolution
