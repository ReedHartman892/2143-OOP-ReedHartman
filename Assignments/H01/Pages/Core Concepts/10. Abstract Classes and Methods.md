# Abstract Classes in C++
A class designed specifically to be used as a base class for other classes. It's good for representing a general concept (like `Shape` or `Animal`) rather than a specific object.

### Key Characteristics
- **Pure Virtual Functions:** A class becomes abstract if it contains at least one pure virtual function. These are declared by appending `= 0` to the function signature.
  ``` cpp
  virtual void draw() = 0; // Pure virtual function
  ```
- **No Instantiation:** You cannot create an object of an abstract class type. Attempting to do so results in a compilation error.
- **Inheritance Requirement:** Any class derived from an abstract class must implement all of its pure virtual functions to become a concrete class (instantiable). If a derived class does not override all pure virtual functions, it also becomes an abstract class.
- **Pointers and References:** While you cannot create objects, you can use pointers and references of the abstract class type to point to objects of its derived classes. This is a core mechanism for achieving polymorphism. 

### Components
In addition to pure virtual functions, an abstract class can contain: 
- **Member Variables:** Data that all derived classes share.
- **Concrete Functions:** Regular functions with full implementations that derived classes can inherit or override.
- **Constructors and Destructors:** Used for initializing and cleaning up shared resources. It is highly recommended to use a virtual destructor in abstract base classes to ensure proper cleanup of derived objects. 

### Restrictions
- Abstract classes cannot be used for variables, member data, function arguments, or return types by value.
- Calling a pure virtual function directly or indirectly from a constructor or destructor results in undefined behavior.

### Interfaces vs. Abstract Classes
Unlike Java or C#, C++ does not have a dedicated interface keyword. 
 - A **pure interface** in C++ is simply an abstract class with only pure virtual functions and no data members.
 - An **abstract class** is used when you want to provide some shared implementation or state alongside the required interface.

## Code Example: Shape System
``` cpp
#include <iostream>
#include <string>

// Abstract Class
class Shape {
protected:
    std::string name;

public:
    Shape(const std::string& n) : name(n) {}

    // Pure virtual function (makes the class abstract)
    virtual void draw() const = 0;

    // Virtual destructor is critical for base classes
    virtual ~Shape() {}

    void printName() const {
        std::cout << "Shape: " << name << std::endl;
    }
};

// Concrete Derived Class
class Circle : public Shape {
private:
    float radius;

public:
    Circle(const std::string& n, float r) : Shape(n), radius(r) {}

    // Implementing the pure virtual function
    void draw() const override {
        std::cout << "Drawing a circle with radius: " << radius << std::endl;
    }
};

int main() {
    // Shape s; // ERROR: Cannot instantiate abstract class

    // Using a pointer to the abstract class for polymorphism
    Shape* myShape = new Circle("MyCircle", 5.5);
    
    myShape->printName(); // Calls base class method
    myShape->draw();      // Calls derived class implementation

    delete myShape;
    return 0;
}
```

## Why It Matters
1. **Enforcing a Uniform Interface:** Abstract classes define a "contract" or protocol that all derived classes must follow. This ensures that every subclass implements specific required methods (pure virtual functions), allowing them to be used interchangeably through base class pointers.
2. **Enabling Polymorphism:** By using pointers or references to an abstract base class, you can write generic code that works with any derived type without knowing the specific type at compile time. For example, a single `Shape*` can point to a `Circle` or a `Square`, and calling `calculateArea()` will invoke the correct version.
3. **Preventing Direct Instantiation:** They prevent the creation of objects that represent an incomplete or "too general" concept (like a generic "Animal" or "Shape" that has no specific properties). This catches logical errors at compile time rather than runtime.
4. **Reducing Code Duplication:** Unlike pure interfaces, abstract classes can provide a partial implementation. They can contain shared data and fully defined methods that all subclasses can inherit and use, which avoids rewriting the same logic in every subclass.
5. **Decoupling Code:** They separate what an object does from how it does it. This loose coupling allows you to update the internal workings of a specific subclass or add new types without breaking the code that uses the high-level interface.
6. **Designing Frameworks and APIs:** Abstract classes are often used in Template Method patterns where a base class defines the skeleton of an algorithm but leaves specific steps for subclasses to fill in, providing a standard structure for external developers to plug into. 

## Common Mistakes
1. **Missing Virtual Destructors:** Failing to declare a virtual destructor in the abstract base class is a critical error. Without it, deleting a derived class object through a base class pointer leads to undefined behavior and memory leaks because the derived destructor is never called.
2. **Attempting Instantiation:** A common beginner error is trying to create an object of an abstract class type. The C++ compiler will flag this as an error because classes with pure virtual functions are incomplete by design.
3. **Object Slicing via Pass-by-Value:** Passing an abstract class by value (e.g., `void func(AbstractClass obj)`) causes object slicing. This strips away the derived parts of the object, typically resulting in a compiler error because abstract types cannot be instantiated to fulfill the by-value parameter. Use pointers or references instead.
4. **Calling Virtual Functions in Constructors/Destructors:** Calling a pure virtual function from a base class constructor or destructor often leads to a crash. During construction of the base part, the derived object (and its virtual table) is not yet fully initialized, so the call cannot be dispatched to the derived override.
5. **Failing to Override All Pure Virtuals:** If a derived class does not redefine every inherited pure virtual function, it remains an abstract class itself and cannot be instantiated. This often happens due to signature mismatches, such as forgetting a `const` qualifier.
6. **Pure Virtual Destructor without Definition:** While you can declare a pure virtual destructor (`virtual ~Base() = 0;`), C++ requires it to have a body because it is always called when a derived object is destroyed.
7. **Over-Abstraction:** Creating deep inheritance hierarchies or "God Interfaces" (too many responsibilities) can make code rigid and hard to maintain. It is often better to favor composition over deep inheritance chains.
