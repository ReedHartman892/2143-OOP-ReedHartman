# Variables in C++
A variable is a named storage location in a computer's memory that holds data and can be modified during program execution.

## Instance Variables
Instance Variables are (specifically) non-static variables declared within a class definition but outside of any method, constructor, or block. The term is often used interchangeably with member variables to refer to the same thing.

 - Ownership: Each object gets it's own separate copy of its class' instance variables.

 - Lifetime: They are created when an object of a class is instantiated and destroyed when the object is destroyed. (provide code example)

 - Scope & Access: Their accessibility is controlled by access specifiers (public, private, protected).

   - private or protected: Only accessible by member functions of the same class or derived classes (for protected).

 - Initialization: Initialization is not compulsory at the time of declaration, but if not initalized it may contain a garbage (indeterminate) data value. (provide code example)

### Common Mistakes
1. Leaving variables uninitialized:
   - Not initalizing a variable causes it to be initialized automatically with a garbage (indetermine) value, which can be dangerous. 
   - You should always initialize instance variables within the class constructor.

2. Direct-accessing variables:
   - Encapsulation Violation: Directly-accessing variables violates encapsulation principles and makes code difficult to maintain, debug, or extend.
   - No Control or Validation: Direct-accessing prevents you from enforcing data integrity. Say you want an integer value to be kept within a hardcoded range. With a setter method in your class definiton, you can program logic to validate input. (provide code example)
   - Refactoring Difficulty: Direct-accessing also risks changing the value of a variable, putting all code that uses said value at risk. Using accessor methods (getters) allows you to control how variables get copied. (provide code example)

### Best Practices (summarized)
1. Use getters and setters in your class definiton. Never directly access.

2. Always initialize all variables of a class within its constructor.
