# Variables in C++
A variable is a named storage location in a computer's memory that holds data and can be modified during program execution.

## Member Variables
    Member variables are variables (also known as data members or fields) declared within a class definiton, but outside any member function. They represent the state or properties of an object instantiated from that class.

### Types of Member Variables
 - Instance Variables (Non-Static)
 - Class Variables (Static)

## Instance Variables
    Instance Variables are (specifically) non-static member variables declared within a class definition outside of any method, constructor, or block.
    
    Each object gets its own separate copy of their class' instance variable, and their lifespan is tied to the object they belong too. (If the object is deleted, their variables go too.)

### Common Mistakes
1. Leaving variables uninitialized:
   - Not initalizing a variable causes it to be initialized automatically with a garbage (indetermine) value, which can be dangerous. 
   - You should always initialize instance variables within the class constructor.

2. Direct-accessing variables:
   - Encapsulation Violation: Directly-accessing variables violates encapsulation principles and makes code difficult to maintain, debug, or extend.
   - No Control or Validation: Direct-accessing prevents you from enforcing data integrity. Say you want an integer value to be kept within a hardcoded range. With a setter method in your class definiton, you can program logic to validate input. (provide code example)
   - Refactoring Difficulty: Direct-accessing also risks changing the value of a variable, putting all code that uses said value at risk. Using accessor methods (getters) allows you to control how variables get copied. (provide code example)

### Best Practices (summarized)
1. Use getters and setters in your class definiton. Never directly access.
2. Always initialize all variables of a class within its constructor.

## Class Variables (Static Member Variables)
    A special data member that is shared by all instances (objects) of a class. Kind of like global variables.

    There is only one copy of the static variable for the entire class, regardless of how many objects are created.

### Characteristics
 - Ownership: All instances of the class share a single copy of the static variable. Modifying it through one object or directly via the class name affects the value for all.
 - Lifetime: Class variables have static storage duration, meaning they're created when the program starts and are destroyed when the program terminates.
 - Scope & Access: Accessed by using the class name and the scope resolution operator ```( :: )```, even if no objects of the class have been created. Like other members, they obey specifiers (public, private, protected)
 - Initialization: Initalized once the program's ```main()``` function starts, and are only destroyed when the program terminates.

### Common Mistakes
1. Overuse: Excessive usage of class variables (static members) indicates a misunderstanding of object-oriented principles. If your class is just a namespace for global functions and variables, then you're not doing OOP correctly.

2. Forgetting the Definition Outside the Class: You must define non-const static member variables outside the class declarion in a single translation unit (usually a .cpp file)

3. Accessing Non-Static Members in Static Functions, aka trying to use a ```this``` pointer to call to a class variable: Minor mistake, but it may happen at one point. Class variables can't use a this variable since they aren't object-specific.

4. Creating Global State: Class variables essentially create global state, which can make code difficult to reason about as widely separated parts of the code can influence the variable.

### Best Practices
1. Use class variables for turly class-wide data (like a total instance count)
2. Use class variables for utility functions that don't depend on object state.
